# YouTube Cookieの登録

「API サーバー設定」でHTTPSのAPI URLとAPIキーを保存し、もう一度設定を開いて「YouTube連携」を選びます。送信先は画面に表示する保存済みのAPIです。設定を編集中は連携ボタンを無効にします。

## iPhoneでログインする

1. 「YouTubeにログイン」を開き、通常のYouTube画面でログインします。
2. ログイン後に「Cookieを取得」を押します。端末のWKWebViewからHttpOnlyを含むCookieを読み取り、YouTube用だけを選別します。
3. 件数と送信先を確認し、「このサーバーにCookieを登録」を押します。
4. 成功すると再生を停止し、古いMix・再生URL・先読みを破棄します。Mixを取得し直してください。

Googleが埋め込みブラウザーでのログインを拒否する場合があります。その場合は戻ってファイル取込を使ってください。外部SafariやYouTubeアプリのCookieを直接読み取ることはできません。Android/Webではファイル取込を利用できます。

## Cookieファイルを取り込む

ブラウザーから書き出したUTF-8のNetscape形式のcookies.txt（1MB以下）を「Cookieファイルを選択」で開き、件数を確認して登録します。`#HttpOnly_`、有効期限、パス、サブドメイン・Secure属性を維持します。対象はyoutube.comとそのサブドメインだけで、期限切れとGoogleなどの別ドメインは除きます。

`LOGIN_INFO`とSAPISID系のCookieの存在を取込時に確認します。これは形式・ログイン用Cookieの有無の確認で、現在のログインの有効性を保証しません。値は画面、診断コピー、アプリのログに表示しません。送信用の本文をアプリ独自の設定ファイルや安全なストレージへ保存せず、取込後はメモリで保持します。WebViewのログイン自体はiOSのWebViewデータストアに保持され、元の取込ファイルもそのまま残ります。

「端末のWebViewログインを消去」は端末のWebViewデータと送信待ちのCookieを消去します。サーバーのCookieは削除しません。サーバー削除用APIは今回の仕様に含まれません。

## 使用するAPI

両方とも保存済みのHTTPSベースURLの下に接続し、`X-API-Key`と`Accept: application/json`を付けます。リダイレクトは追跡しません。

| 操作 | リクエスト | 成功応答 |
| --- | --- | --- |
| 登録・更新 | `PUT /youtube/cookies`、`Content-Type: text/plain`、本文はNetscape形式テキスト、タイムアウト120秒 | `configured: true`、更新時刻 |
| 保存状態の確認 | `GET /youtube/cookies`、本文なし | `configured: true/false`、更新時刻 |

アプリは`configured`を必須の真偽値として読み、`updated_at`が日時文字列なら更新時刻を表示します。更新時刻のフィールドがない場合も登録・保存状態の表示は動作します。

登録したCookieはサーバーが再起動後も保持します。GETは保存状態の確認で、ログインの有効性確認ではありません。サーバーは登録時とMix取得時に有効性を確認します。アプリはGETの結果を「保存済み／未登録」と表示します。

HTTP 404/501は未対応APIとして案内します。401/403/422、タイムアウト、通信障害、不正な応答では成功扱いにせず、取込済みのCookieを再送できます。サーバーのエラー本文やCookie値は表示しません。タイムアウト後はサーバー側で登録が終わっている可能性があるため、「保存状態を確認」で再確認できます。

`/mix`、`/stream`、`/mix/{session_id}/extend`の形式は変更しません。credential IDや追加の認証ヘッダー、DELETE APIは使いません。各リクエストにCookie本文を再送せず、サーバー側で登録済みのCookieを使う既存仕様に従います。

このリポジトリにはサーバー実装を含めません。Cookieを使っても、YouTubeのおすすめが別のブラウザーと完全に一致することや、再生URLの取得が速くなることは保証されません。Cookieが失効した場合は再取得して登録してください。
