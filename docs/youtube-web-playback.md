# YouTubeのページから再生する

API URLとAPIキーを保存した後、メイン画面の「YouTubeを開く」を押します。YouTubeで検索し、動画をタップしてください。動画ページへの移動後にAPIから再生URLを取得し、Mix Playerで再生します。ログインは「API サーバー設定」→「YouTube連携」と同じWebViewの保存領域を使います。

## 再生と画面

- 通常の動画はその1本だけを再生します。以前のMixへ自動で続きません。Shorts・ライブの動画ページ、youtu.beからのリンクも動画IDで判定します。
- YouTubeの「ミックス」（URLの`list=RD…`）を選んだ場合だけ、Mixを20曲取得して連続再生します。通常の再生リスト（`list=PL…`など）の動画は単曲として扱います。
- Mixは選んだ動画から再生します。その動画がAPIの一覧にない場合は、別の曲を流さずエラーと再試行を表示します。
- 「音声のみ／動画＋音声」はメイン画面で選んだモードを引き継ぎます。動画モードではアプリの動画枠を表示します。
- 再生・一時停止・停止・シーク・Mixの前後移動は、画面下のMix Playerの操作バーを使ってください。YouTubeページ内の音声・動画は停止して二重再生を防ぎます。
- Mixの曲が自動で変わった場合や、操作バーで前後に移動した場合、YouTubeページもその曲へ移ります。このページ移動で音源を再取得したり、曲の先頭から再生し直したりしません。
- ブラウザーを閉じてもアプリの再生は継続します。閉じた状態やバックグラウンドではページ移動を保留し、再度開く・復帰した際に現在曲へ同期します。動画のバックグラウンド再生は従来どおり一時停止します。
- 停止した動画は、残っているページの「この動画を再生」で再開できます。ページの戻る・進む・ホーム・再読込も利用できます。

## 通信とCookie

動画ページへの通常の移動と、YouTubeのSPAによるURL変更の両方を検出します。移動をキャンセルして先にアプリを再生する方式ではなく、現在のページURLが確定してから再生要求を出します。検索・ログインページや外部サイトからは再生要求を出しません。

単曲は既存の`POST /stream`（`video_id`、`include_formats=false`）、Mixは既存の`POST /mix`（`url`、`count=20`）を使用します。Mixの追加取得・先読み、URLキャッシュ、有効期限判定、メディア用`http_headers`の引継ぎは既存の処理を使います。APIキーをYouTubeのWebViewやメディア配信先へ渡しません。APIの追加・サーバー実装の変更はありません。

WebViewでログインしただけでは、サーバーにCookieを登録し直しません。必要なときは既存の「YouTube連携」から登録してください。[Cookie登録の操作・API仕様](youtube-cookie-api.md)を参照してください。

閲覧・連携機能はiPhone／Androidアプリ向けです。Web検証版は従来のMix取得・再生を維持します。実際のYouTubeページ、Googleのログイン可否、APIの抽出結果、iOSのバックグラウンド動作は端末で確認してください。
